2D mode

The relay passes VGA IN straight to VGA OUT. The card is invisible to the monitor, and stays that way if the FPGA is unconfigured, crashed or unpowered. HDMI shows a status screen or the menu.

3D mode

Glide opens the device, the relay switches, and the ADV7123 drives VGA OUT from the fabric's video timing. HDMI carries the same frame, scaled to 720p or 1080p with integer scaling and optional scanlines.

What v1 leaves unpopulated

The TVP7002 capture ADC and its front end. VGA IN is routed to the ADC inputs through series resistors that are not placed, so the empty footprint puts no load on the passthrough. Its 24 data pins, syncs and I2C are assigned on the FPGA pinout and the capture path stays in the design.

When it is placed, HDMI shows the 2D desktop as well, and the card becomes the whole PC's modern output.

Memory where the original's three EDO buses go

The Artix-7 has 13.1 Mbit of block RAM, about 1.6 MB. That is not enough for two colour buffers plus depth at 640×480, so the layout splits by access pattern. The read-modify-write path stays on chip; the streaming paths go to HyperRAM and DDR3. The HyperRAM is the ISSI IS66WVH8M8BLL-100B1LI: 64 Mbit, HyperBus, 3.0V, 100 MHz, in LCSC stock at about $1.92, and the device the open MJoergen controller was developed on. The Infineon S27KL0642 is the same-footprint, same-voltage 200 MHz upgrade if ever needed.

What the T113 does the MiSTer split, applied here

  • Boots Linux from SPI NAND. Holds the FPGA bitstream and rewrites the FPGA's QSPI flash for field updates over USB or Ethernet.
  • Serves the on-screen menu on HDMI over SPI: scaler mode, scanlines, VGA timing, relay override.
  • Runs SpinalVoodoo's existing Glide runtime against the core. The 24-bit LCD port, driven as a one-way parallel pipe at over 100 MB/s, is fast enough to play games from the ARM with no host PC in the slot.
  • USB 2.0 host for a keyboard or gamepad in menus and self-test.
  • Collects performance counters: triangles per second, FIFO stalls, cache hit rate, frame time.
  • Takes screenshots and traces for regression against the pixel-exact reference model.
  • Never sits in the pixel or PCI path. Config-space cycles must answer within a few PCI clocks, so that stays in fabric.

Basic BOM variant same board, Voodoo 1 only

The core sets the floor: SpinalVoodoo's Voodoo 1 needs about 45K LUT6 with PCI, HyperRAM controllers and video, so nothing smaller than an Artix-7 100T holds it. A dedicated smaller board saves only $10 to $15 against populating this layout differently, so the basic card is a BOM, not a second design. It relies on the 484-ball footprint compatibility between the 100T and 200T, which is on the verify list.

What the basic card is: a register-level Voodoo 1 that runs the original drivers, 640×480 with Z, VGA passthrough and HDMI. What it gives up: Voodoo 2, Linux and networking, and some speed. The 100T's 4.9 Mbit of BRAM cannot hold the depth buffer, so depth goes to HyperRAM behind the read cache. Expect 60% to 100% of a real Voodoo 1, which a Pentium host cannot tell apart from the original. A dedicated 4-layer board on an ECP5-85, about $75 a card at 200 units, is the only way to go cheaper, and it needs its own toolchain and controller port.

Phases each ends with something that runs

  1. Port SpinalVoodoo to an Artix-7 200T PCIe dev board
    An Alinx or QMTech 200T board with DDR3 and PCIe, about $200 to $300, in a Linux PC. Avalon ports become AXI and MIG; the DE10 MMIO runtime maps the PCIe BARs through UIO, which is the same memory-mapped model. Move the framebuffer into BRAM and HyperRAM and measure the small-triangle numbers again.
    exit: Quake and Screamer 2 run at or above real Voodoo 1 rates; real LUT and BRAM usage known
  2. Card rev B
    PCI target with config space, T113, relay, DAC, HDMI, HyperRAM, ADC footprint. Bring up on a Socket 7 board with DOS Glide and the Win9x reference drivers.
    exit: unmodified 3dfx Voodoo 1 drivers enumerate and run the card
  3. Voodoo 2 extensions
    Second TMU with multi-texture chaining, cmdFifo triangle packets, memory FIFO, 128-entry PCI FIFO, 90 MHz timing closure. Validate against MAME and 86Box traces.
    exit: Voodoo 2 drivers run; core under 75K LUT6
  4. v2 firmware
    Place the ADC. Capture, scaler and menu in fabric, controlled from the T113. HDMI now shows the whole session.
    exit: one HDMI cable from a 1998 PC
  5. Combo card: 2D + 3D in one slot
    A firmware and BOM variant on the same board, no relayout. The card becomes a two-function PCI device: function 0 is an SVGA adapter built on the ao486 VGA core with the Bochs VBE extension, function 1 is the Voodoo 2. The VGA frame buffer lives in DDR3 behind a scanline FIFO; the passthrough relay is replaced by a video mux in the fabric, switched by the same register bit the 3dfx driver already flips, so VGA IN and the relay go unpopulated. Software is all existing and open: the Bochs VGABIOS as the option ROM served from config space and held by the T113, vmdisp9x as the Windows 9x display driver with its DirectDraw HAL, VESA 2.0 for DOS, and 3dfx's own Voodoo 2 drivers for Glide, Direct3D and the MiniGL and OpenGL ICD, exactly as on a 1998 PC with two cards. About 5K LUT6 extra, no 2D acceleration in this step. Later upgrade for the 2D function: GPLGPU's Imagine 128 core (in-box Windows 98 driver, BitBLT, needs a memory-controller port and a video BIOS) or a Cirrus CL-GD5446 core written against QEMU (in-box driver, SeaVGABIOS).
    exit: Windows 98 desktop and Glide games from one card, one VGA cable, one HDMI, no drivers written

Expansion ports low-speed I/O the 1995 way

The card carries internal ribbon headers to slot-cover brackets, the same system PCs used for COM, LPT and game ports. The pinouts are de facto standards and bracket cables cost $2 to $5. Transceivers live on the main board next to each header. No module standard is invented until there is demand for one.

The FPGA does the legacy address decode on the PCI bus. Positive decode by a PCI device beats the chipset's subtractive decode to ISA, so with the motherboard's own ports disabled in the BIOS, DOS and Windows 98 see ordinary COM1, LPT1 and an MPU-401 and use their in-box drivers. Open cores exist for all of them. Interrupts are the one wrinkle: the card can only raise INTA#, so DOS software that assumes IRQ 4 or 7 needs the BIOS to route the slot's interrupt there, which most boards of the era allow once the on-board ports are off. Windows does not care, and polled operation always works. Cost: about $4 of parts and roughly 30 FPGA pins for two serial, one parallel and one MIDI port, plus 16 pins for the two Pmods.

Bracket width finding. The main bracket is already full. Two DB15 at 31 mm, HDMI at 15, USB-A at 14 and RJ45 at 16 total about 107 mm against about 95 mm usable on a full-height bracket. A stacked RJ45-over-USB jack just fits; the cleaner answer is a second slot-cover bracket for the T113's USB and Ethernet, and once that bracket exists the expansion ports ride along on it. Decide before connector selection.

Open risks check before ordering boards

Grey-channel FPGAs. DigiKey lists the 200T near $250; LCSC stock at $80 is pulls or relabels. Buy samples first, check date codes, test them, then buy the whole run and consign it to assembly.
Block RAM budget. Depth buffer, texture caches and FIFOs all want the same 13 Mbit. Phase 1 must report the real split before the memory subsystem is frozen.
T113 power sequencing. Three or four rails in order, plus a 128-ball BGA. Copy a known-good reference design (MangoPi MQ-Dual) rather than deriving it.
Tools. AMD's free Vivado tier for 2026.1 is reported as Windows-only. Plan the build machine, or pin an earlier release.
License. SpinalVoodoo's repository shows no license file. Ask the author before building a product on it.
